# Create with Server Actions

## Day 4 - ชั่วโมงที่ 3: บันทึก Issue ด้วย Server Action

### เป้าหมายของชั่วโมงนี้

หลังจบชั่วโมงนี้ นักศึกษาจะสามารถ:

1. อธิบายหน้าที่ของ Server Action ได้
2. อ่านและตรวจข้อมูลจากฟอร์มบน Server
3. เพิ่ม Issue ใหม่ลง Supabase
4. ให้ `IssueForm` ส่งข้อมูลไปที่ Server Action

### ไฟล์ที่ใช้

```text
types/issue.ts              ← แก้ไข
app/actions.ts              ← สร้างใหม่
lib/issues.ts               ← แก้ไข
components/IssueForm.tsx    ← แก้ไข
app/issues/new/page.tsx     ← แก้ไข
```

## Slide 1: จาก Read ไปสู่ Create

หน้า `/issues` และหน้ารายละเอียดอ่านข้อมูลจาก Supabase แล้ว แต่ฟอร์มยังเป็นของ Day 3 ที่เก็บข้อมูลใน Browser

ชั่วโมงนี้จะให้ฟอร์มบันทึกลง Database:

```text
IssueForm → Server Action → ตรวจข้อมูล → เพิ่มลง Supabase → กลับไปหน้า /issues
```

โค้ดอ่านและตรวจข้อมูลจาก Day 3 จะย้ายจาก `IssueForm` ไปทำงานบน Server

---

## Slide 2: Server Action คืออะไร

**Server Action** คือ `async function` ที่ทำงานบน Server และฟอร์มเรียกได้โดยตรงผ่าน `action`:

```tsx
<form action={createIssueAction}>
  {/* ช่องกรอกเดิม */}
</form>
```

เมื่อกดส่งฟอร์ม:

1. Browser รวบรวมค่าจากช่องกรอกที่มี `name` เป็น `FormData`
2. Next.js ส่ง `FormData` ไปให้ `createIssueAction` บน Server
3. Action ตรวจข้อมูลแล้วบันทึกลง Database

ต้องตรวจข้อมูลซ้ำบน Server เพราะคนอื่นส่งข้อมูลตรงมาโดยไม่ผ่านฟอร์มได้

## Slide 5: อ่านค่าจาก FormData

<LessonCallout type="action">เพิ่ม Function ใหม่ `parseIssueInput` ใน `app/actions.ts` ต่อจาก Import</LessonCallout>

function parseIssueInput(formData: FormData): NewIssueInput {

## Slide 6: ตรวจข้อมูลบน Server

<LessonCallout type="action">ย้าย Function `validateIssueInput` จาก `components/IssueForm.tsx` มาวางใน `app/actions.ts` ต่อจาก `parseIssueInput`</LessonCallout>

<CodeChange language="ts" addedLines="1,2,3,4,5,6,7,8">

```ts
function validateIssueInput(input: NewIssueInput): string[] {
  const errors: string[] = [];
  if (input.reporterName.length < 2) errors.push("ชื่อผู้แจ้งต้องมีอย่างน้อย 2 ตัวอักษร");
  if (!input.reporterEmail.includes("@")) errors.push("กรุณาตรวจสอบอีเมลผู้แจ้ง");
  if (input.title.length < 5) errors.push("หัวข้อปัญหาต้องมีอย่างน้อย 5 ตัวอักษร");
  if (input.description.length < 10) errors.push("รายละเอียดต้องมีอย่างน้อย 10 ตัวอักษร");
  return errors;
}
```

</CodeChange>

โค้ดเหมือน Day 3 ทุกบรรทัด ใช้ตัดแล้ววางได้เลย

ตอนนี้ `IssueForm.tsx` จะขึ้น Error ว่าหา `validateIssueInput` ไม่พบ ไม่เป็นไร Slide 11 จะลบส่วนที่เรียกใช้ออก

## Slide 9: สร้าง Action ที่ฟอร์มเรียก

<LessonCallout type="action">แก้บางส่วนใน `app/actions.ts`: เพิ่ม Import ต่อจาก Type Import แล้วเพิ่ม `createIssueAction` ท้ายไฟล์</LessonCallout>

<CodeChange language="ts" addedLines="1,2,3">

```ts
import { revalidatePath } from "next/cache";
import { redirect } from "next/navigation";
import { createIssue } from "@/lib/issues";
```

</CodeChange>

<CodeChange language="ts" addedLines="1,2,3,4,6,7,8,9">

```ts
export async function createIssueAction(formData: FormData) {
  const input = parseIssueInput(formData);
  const errors = validateIssueInput(input);
  if (errors.length > 0) throw new Error(errors.join(", "));

  await createIssue(input);
  revalidatePath("/issues");
  redirect("/issues");
}
```

</CodeChange>

`revalidatePath` ให้หน้า `/issues` อ่านข้อมูลใหม่ แล้ว `redirect` พาไปหน้านั้น

## Slide 16: ถ้าบันทึกไม่สำเร็จ

| อาการ | ตรวจที่ |
|---|---|
| กดส่งแล้วไม่มีอะไรเกิดขึ้น | `<form>` ใช้ `action={createIssueAction}` |
| ค่าที่ได้เป็นข้อความว่าง | `name` ของช่องกรอกตรงกับ `formData.get(...)` |
| ขึ้น `permission denied` | `grant` และ Policy `demo_insert_issues` ใน Hour 1 |
| ไปหน้า `/issues` แล้วไม่เห็นรายการใหม่ | `revalidatePath("/issues")` |

ถ้าข้อมูลไม่ผ่าน `validateIssueInput` จะเห็นหน้า Error และข้อมูลไม่ถูกบันทึก ตอนนี้ `minLength` ช่วยกันกรณีนี้ไว้ก่อนแล้ว

## คำศัพท์สำคัญ

| คำศัพท์ | ความหมาย |
|---|---|
| Server Action | Function บน Server ที่ฟอร์มเรียกได้ผ่าน `action` |
| `FormData` | ค่าจากฟอร์มที่เก็บตาม `name` ของช่องกรอก |
| `.insert()` | เพิ่มแถวใหม่ลง Table |
| `revalidatePath()` | บอกให้หน้าที่กำหนดอ่านข้อมูลใหม่ |
| `redirect()` | พาผู้ใช้ไปยัง URL อื่นหลังทำงานเสร็จ |
