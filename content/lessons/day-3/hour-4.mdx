# Mock CRUD and Database Prep

## Day 3 - ชั่วโมงที่ 4: เปลี่ยนสถานะใน Mock State

### เป้าหมายของชั่วโมงนี้

หลังจบชั่วโมงนี้ นักศึกษาจะสามารถ:

1. อธิบาย Create, Read และ Update ในโปรเจกต์ปัจจุบันได้
2. เปลี่ยน Status ของ Issue ใน State ได้
3. Update Array และ Object แบบไม่แก้ค่าเดิมโดยตรง
4. ส่ง Event Handler จาก Parent ไปยัง Child ผ่าน Props
5. ทำให้ `IssueList` ใช้ได้ทั้งแบบอ่านอย่างเดียวและแบบแก้สถานะได้
6. อธิบายข้อจำกัดของ Mock State ก่อนเชื่อม Database ได้

### ไฟล์ที่แก้

```text
components/IssueBoard.tsx
components/IssueList.tsx
```

---

## Slide 1: เพิ่มการเปลี่ยนสถานะต่อจาก Hour 3

หน้า Home สร้าง Issue ใหม่ได้แล้ว โดย `IssueBoard` เก็บ `items` และส่งให้ `IssueList`

ชั่วโมงนี้จะให้ List ส่ง `id` และสถานะที่เลือกกลับไปให้ Board เปลี่ยน State

- **Create:** เพิ่มรายการจาก Form ได้แล้ว
- **Read:** แสดงรายการจาก State ได้แล้ว
- **Update:** กำลังจะเพิ่มการเปลี่ยนสถานะ
- **Delete:** ไม่เพิ่มใน Project นี้ ใช้ `DONE` เพื่อระบุว่างานเสร็จแล้ว

ทั้งสี่คำเรียกรวมกันว่า CRUD ส่วนข้อมูลยังอยู่ชั่วคราวใน Browser

---

## Slide 2: เปลี่ยน State ด้วยข้อมูลชุดใหม่

ตัวอย่างอธิบายที่ไม่ควรใช้ ไม่ต้องนำไปแก้ Project:

```tsx
issue.status = "DONE";
setItems(items);
```

การส่ง Array เดิมกลับเข้า State อาจทำให้ React ข้ามการ Render เพราะ Reference ยังเป็นตัวเดิม

วิธีที่เราจะใช้:

1. `.map()` สร้าง Array ใหม่จากรายการเดิม
2. ถ้า `id` ตรง ให้สร้าง Object ใหม่ด้วย `{ ...issue, status }`
3. ถ้า `id` ไม่ตรง ให้คืน Object เดิม

เรียกว่า **Immutable Update** คือสร้างข้อมูลชุดใหม่โดยไม่แก้ต้นฉบับ

## Slide 3: เพิ่ม Handler ที่เป็นเจ้าของ State

<LessonCallout type="action">แก้บางส่วนใน `components/IssueBoard.tsx`: เพิ่ม `IssueStatus` ใน Type Import เดิม และเพิ่ม Handler ตามตำแหน่งด้านล่าง</LessonCallout>

<CodeChange language="tsx" addedLines="1">

```tsx
import type { Issue, IssueStatus } from "@/types/issue";
```

</CodeChange>

เพิ่ม Function นี้ภายใน `IssueBoard` หลัง `handleCreateIssue` และก่อน `return`:

<CodeChange language="tsx" addedLines="1,2,3,4,5,6,7">

```tsx
function handleUpdateStatus(id: string, status: IssueStatus) {
  setItems((currentItems) =>
    currentItems.map((issue) =>
      issue.id === id ? { ...issue, status } : issue
    )
  );
}
```

</CodeChange>

`id` ระบุรายการที่จะเปลี่ยน ส่วน `status` คือค่าใหม่; เก็บ State และ Handler สร้างรายการเดิมไว้

## Slide 4: อ่านการอัปเดตทีละขั้น

ตัวอย่างอธิบายจาก Handler ที่เพิ่งเพิ่ม:

```tsx
issue.id === id ? { ...issue, status } : issue
```

- `เงื่อนไข ? ค่าถ้าจริง : ค่าถ้าเท็จ` เลือกว่าจะคืนค่าใด
- `...issue` คัดลอกทุก Field เดิม เช่นหัวข้อและผู้แจ้ง
- `status` ที่เขียนตามหลังแทนเฉพาะสถานะด้วยค่าใหม่

`setItems` ส่งรายการล่าสุดให้ `currentItems` และ `.map()` คืน Array ใหม่ โดยจำนวนรายการเท่าเดิม

เมื่อกดเปลี่ยนสถานะ จึงควรเปลี่ยนเพียง Badge ของรายการที่เลือก ไม่สร้าง Row เพิ่ม

## Slide 5: List เดียวรองรับสองหน้า

`IssueList` ถูกใช้สองจุด และต้องรองรับทั้งคู่:

| จุดที่เรียกใช้ | พฤติกรรมที่ต้องการ |
|---|---|
| Home ผ่าน `IssueBoard` | แสดงปุ่มและเปลี่ยน State ได้ |
| `/issues` ผ่าน `app/issues/page.tsx` | แสดงข้อมูลอย่างเดียว |

เราจะเพิ่ม Callback ชื่อ `onUpdateStatus` เป็น **Optional Prop** ด้วย `?` เหมือน Callback ของ Form ใน Hour 3

ส่ง Callback มา → แสดง Column จัดการ; ไม่ส่งมา → ซ่อนทั้งหัว Column และช่องปุ่ม

หน้า `/issues` จึงยังใช้ `<IssueList issues={issues} />` เดิมได้

## Slide 8: เพิ่มหัว Column เมื่อมี Callback

<LessonCallout type="action">เพิ่ม JSX ใหม่ใน `components/IssueList.tsx`: ภายใน `<thead>` และ `<tr>` วางเงื่อนไขต่อจาก `<th>` รายละเอียด ก่อน `</tr>`</LessonCallout>

<CodeChange language="tsx" addedLines="2,3,4">

```tsx
<th className="px-3 py-3 font-semibold">รายละเอียด</th>
{onUpdateStatus && (
  <th className="px-3 py-3 font-semibold">จัดการ</th>
)}
```

</CodeChange>

บรรทัด “รายละเอียด” เป็นจุดอ้างอิงเดิม ไม่เพิ่มซ้ำ

`onUpdateStatus && (...)` แสดงหัว Column เมื่อมี Callback เท่านั้น ตอนนี้ยังไม่เห็น Column เพราะ Board ยังไม่ได้ส่ง Callback

## Slide 9: เตรียมช่องปุ่มในแต่ละแถว

<LessonCallout type="action">เพิ่ม JSX ใหม่ใน `components/IssueList.tsx`: ภายใน `issues.map()` วางหลัง `<td>` รายละเอียด และก่อน `</tr>` ของแถวนั้น</LessonCallout>

<CodeChange language="tsx" addedLines="1,2,3,5,6,7">

```tsx
{onUpdateStatus && (
  <td className="px-3 py-4">
    <div className="flex flex-wrap gap-2">
      {/* เพิ่มปุ่มสถานะตรงนี้ในขั้นถัดไป */}
    </div>
  </td>

```

</CodeChange>

เมื่อมี Callback จึงสร้างช่องจัดการให้ตรงกับหัว Column; เก็บ Cell รายละเอียดและ Link เดิมไว้

Comment เป็นจุดวางปุ่มในขั้นถัดไป ส่วน `flex-wrap` จะช่วยให้ปุ่มขึ้นบรรทัดใหม่ได้

## Slide 10: สร้างปุ่มจากรายการสถานะ

<LessonCallout type="action">เพิ่ม JSX ใหม่ใน `components/IssueList.tsx`: แทน Comment ภายในกล่องปุ่มด้วยโค้ดนี้ โดยเก็บ `<td>`, `<div>` และเงื่อนไขด้านนอกไว้</LessonCallout>

<CodeChange language="tsx" addedLines="1,2,3,4,5,6,7,8,9">

```tsx
{statuses.map((status) => (
  <button
    key={status} type="button"
    disabled={issue.status === status}
    onClick={() => onUpdateStatus(issue.id, status)}
  >
    {status}
  </button>
))}
```

</CodeChange>

ตัวอย่างเริ่มที่ `.map()` เมื่อวางจริงให้เยื้องเข้าไปภายใน `<div>` ของช่องปุ่ม

`onClick` เรียก Callback ตอนคลิก; `disabled` ปิดปุ่มสถานะปัจจุบัน และ `type="button"` ระบุว่าไม่ใช่ปุ่มส่ง Form

## Slide 11: ตกแต่งปุ่มสถานะ

<LessonCallout type="action">แก้บางส่วนใน `components/IssueList.tsx`: เพิ่ม `className` ให้ Tag เปิดของปุ่มภายใน `statuses.map()`</LessonCallout>

<CodeChange language="tsx" addedLines="5,6,7,8">

แสดงเฉพาะ Tag เปิด ให้เก็บ `{status}`, `</button>` และโครง `.map()` เดิมไว้

## Slide 14: ลองเปลี่ยนสถานะที่ Home

<LessonCallout type="action">เปิดหน้า Home `/` แล้วทดสอบปุ่มกับทั้งรายการเดิมและรายการที่เพิ่มใหม่</LessonCallout>

1. เลือกรายการที่เป็น `OPEN` แล้วกด `IN_PROGRESS`: Badge ต้องเป็นสีเหลือง
2. กด `DONE`: Badge ต้องเป็นสีเขียว และปุ่ม `DONE` กดไม่ได้
3. ตรวจว่าจำนวน Row และข้อมูลของรายการอื่นไม่เปลี่ยน
4. เพิ่มรายการใหม่จาก Form แล้วลองเปลี่ยนสถานะของรายการใหม่นั้น
5. กด Tab ไปยังปุ่มสถานะ ต้องเห็นตำแหน่ง Focus และใช้ Enter กดได้

Demo นี้เลือกกลับไปสถานะอื่นได้ ยังไม่ได้จำกัดลำดับการเปลี่ยนสถานะ

## Slide 15: ตรวจหน้าอ่านอย่างเดียวและจอเล็ก

<LessonCallout type="action">เปิด `/issues` แล้วใช้ DevTools ตรวจทั้ง `/` และ `/issues` ที่ความกว้าง 375px และ 1024px</LessonCallout>

- `/issues` ต้องมีห้า Column เดิม ไม่มีหัวข้อ “จัดการ” และไม่มีปุ่มสถานะ
- Link รายละเอียดของ Mock Data ต้องยังเปิดได้
- Empty State เดิมยังอยู่ก่อน `return` หลักและไม่ขึ้นกับ Callback
- ที่ 375px และ 1024px ตารางที่กว้างเกินพื้นที่ต้องเลื่อนภายในกล่อง ไม่ดันทั้งหน้า
- Console และ Terminal ต้องไม่มี Error

สถานะที่เปลี่ยนใน Home ยังไม่แสดงใน `/issues` เพราะหน้านี้อ่าน Mock Data เดิม

## Slide 16: จาก State ชั่วคราวไปสู่ Database

ตอนนี้ Home เพิ่มรายการและเปลี่ยนสถานะได้ แต่ข้อมูลยังอยู่ใน State ของ `IssueBoard`

| ตอนนี้ | หลังเชื่อม Database ใน Day 4 |
|---|---|
| Refresh แล้วการเพิ่มและแก้หาย | บันทึกแล้วอ่านกลับได้ |
| Route อื่นอ่าน Mock Data เดิม | ทุก Route อ่านแหล่งข้อมูลเดียวกัน |
| เปลี่ยนเฉพาะใน Browser นี้ | Browser อื่นอ่านค่าที่บันทึกแล้วได้ |

ขั้นต่อไปคือสร้าง Supabase Project และ Table ก่อนย้ายการอ่านและบันทึกไปฝั่ง Server

Server ยังต้องตรวจข้อมูลและสิทธิ์; การซ่อนปุ่มใน Client เป็นเพียงการจัด UI
