# Issue List and Git

## Day 1 - ชั่วโมงที่ 4: เพิ่ม Issue List และบันทึกงานด้วย Git

### เป้าหมายของชั่วโมงนี้

หลังจบชั่วโมงที่สี่ ผู้เรียนควรสามารถ:

1. เพิ่มรายการปัญหาแบบ Static ต่อจาก Form เดิมได้
2. ใช้ HTML Table แสดงข้อมูลหลายรายการได้
3. ทำให้ Table ใช้งานบนหน้าจอเล็กได้
4. สร้าง Status Badge ที่สื่อความหมายด้วยข้อความและสีได้
5. เข้าใจความแตกต่างระหว่าง Git และ GitHub
6. Commit และ Push งาน Day 1 ขึ้น GitHub ได้

### ไฟล์ที่ใช้ในชั่วโมงนี้

```text
index.html
style.css
```

คำสั่ง Git ให้รันใน Terminal ที่เปิดอยู่ใน Project Folder

## Slide 1: จาก Form ไปสู่รายการปัญหา

ตอนนี้หน้าเว็บของเรามี:

- Header แสดงชื่อระบบ
- Form สำหรับกรอกข้อมูลปัญหา
- CSS ที่รองรับหน้าจอเล็กและหน้าจอกว้าง
- Footer แสดงข้อมูลส่วนท้าย

Hour นี้เราจะเพิ่ม **Issue List** ต่อจาก Form เพื่อให้เห็นตัวอย่างปัญหาที่เข้าสู่ระบบ แล้วบันทึกงาน Day 1 ด้วย Git

## Slide 2: ตอนนี้ยังเป็น Static Prototype

| ส่วนของหน้า | หน้าที่ที่กำลังจำลอง |
|---|---|
| Form แจ้งปัญหา | หน้าตาของการสร้างข้อมูล หรือ Create |

## Slide 3: เพิ่ม Section สำหรับ Issue List

<LessonCallout type="action">แก้บางส่วนใน `index.html`: เพิ่ม Section ต่อจาก Form และก่อน `</main>`</LessonCallout>

แต่ละแถวจะแสดงรหัส หัวข้อ ผู้แจ้ง และสถานะ เพื่อให้เปรียบเทียบหลายรายการได้ง่าย

<CodeChange
  language="html"
  addedLines="1,2,3,5,6,7,8"
>


</CodeChange>

`aria-labelledby` เชื่อม Section กับหัวข้อ `issue-list-title` ทำให้เครื่องมือช่วยการเข้าถึงรู้ว่า Section นี้เกี่ยวกับอะไร

## Slide 8: สร้าง Status Badge สามสถานะ

<LessonCallout type="action">เพิ่ม Style พื้นฐานและสีของ Badge ต่อใน `style.css`</LessonCallout>

จาก HTML ใน Table:

```html
<span class="status status-open">OPEN</span>
```

- `status` คือ Style พื้นฐานที่ใช้ร่วมกันทุกสถานะ
- `status-open` คือสีเฉพาะของสถานะ `OPEN`

เพิ่ม Style พื้นฐานต่อใน `style.css`

```css
.status {
  display: inline-block;
  border-radius: 999px;
  padding: 4px 10px;
  font-size: 12px;
  font-weight: 700;
}

.status-open {
  background: #fee2e2;
  color: #991b1b;
}

.status-progress {
  background: #fef3c7;
  color: #92400e;
}

.status-done {
  background: #dcfce7;
  color: #166534;
}
```

`status` คือ Style ที่ใช้ร่วมกัน ส่วน Class ที่สองกำหนดสีเฉพาะสถานะ สีช่วยให้มองหาได้เร็ว แต่ยังต้องมีข้อความ `OPEN`, `IN_PROGRESS` และ `DONE` เพราะผู้ใช้บางคนอาจแยกสีได้ยาก

## Slide 10: Git และ GitHub ต่างกันอย่างไร

| คำ | ความหมาย |
|---|---|
| Git | โปรแกรมที่บันทึกประวัติการเปลี่ยนแปลงของ Project บนเครื่อง |
| GitHub | เว็บไซต์ที่ใช้เก็บ Git Repository และแชร์งานกับผู้อื่น |
| Repository | Project ที่ Git กำลังติดตาม |
| Commit | จุดบันทึกการเปลี่ยนแปลงหนึ่งครั้ง |
| Push | ส่ง Commit จากเครื่องขึ้น GitHub |

Git ใช้งานบนเครื่องได้โดยไม่ต้องมี GitHub แต่เราจะใช้ทั้งสองอย่างเพื่อเก็บงานไว้บนเครื่องและ Online

## Slide 11: Workflow ที่ใช้บันทึกงาน

```text
แก้ไฟล์
   ↓
git status       ตรวจว่ามีไฟล์ใดเปลี่ยน
   ↓
git add .        เลือกการเปลี่ยนแปลงสำหรับ Commit
   ↓
git commit       บันทึกการเปลี่ยนแปลง
   ↓
git push         ส่ง Commit ขึ้น GitHub
```

`git add` ยังไม่ใช่การบันทึกถาวร ขั้นตอนที่สร้างจุดบันทึกจริงคือ `git commit`

## Slide 12: เริ่มให้ Git ติดตาม Project

<LessonCallout type="action">เปิด Terminal ใน Folder ที่มี `index.html` และ `style.css` แล้วตรวจสถานะ Repository</LessonCallout>

```bash
git init
git status
```

- `git init` สร้าง Git Repository ใน Folder ปัจจุบัน โดยใช้เพียงครั้งแรก
- `git status` แสดงสถานะของไฟล์และใช้ตรวจว่าเราเปิด Terminal ถูก Folder หรือไม่

หาก Project นี้เป็น Git Repository อยู่แล้ว ไม่ต้องรัน `git init` ซ้ำ

---

## Slide 13: สร้าง Commit แรก

<LessonCallout type="action">เลือกไฟล์ ตรวจรายการ แล้วสร้างจุดบันทึกแรก</LessonCallout>

```bash
git add .
git status
git commit -m "Create Day 1 static issue page"
```

- `.` หมายถึงไฟล์ทั้งหมดภายใน Folder ปัจจุบัน
- `git status` รอบที่สองช่วยตรวจไฟล์ก่อน Commit
- ข้อความหลัง `-m` อธิบายสั้น ๆ ว่า Commit นี้สร้างอะไร

ตรวจ Commit ที่เพิ่งสร้างด้วย:

```bash
git log --oneline
```

## Slide 14: เชื่อมและ Push งานขึ้น GitHub

<LessonCallout type="action">สร้าง Repository ว่างบน GitHub โดยไม่เพิ่ม README แล้วเชื่อมกับ Project นี้</LessonCallout>

```bash
git branch -M main
git remote add origin https://github.com/username/repository-name.git
git push -u origin main
```

- `git branch -M main` ตั้งชื่อ Branch หลักเป็น `main`
- `git remote add origin` เชื่อม Project บนเครื่องกับ Repository บน GitHub
- `git push -u origin main` ส่ง Commit ขึ้น GitHub และจำปลายทางสำหรับการ Push ครั้งถัดไป
