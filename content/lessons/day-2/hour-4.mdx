# Components and Routing

## Day 2 - ชั่วโมงที่ 4: แยก Component และสร้างหน้าใหม่

### เป้าหมายของชั่วโมงนี้

หลังจบชั่วโมงนี้ ผู้เรียนจะสามารถ:

1. อธิบายได้ว่าทำไมไม่ควรเก็บ Type, Data และ UI ทั้งหมดไว้ใน `page.tsx`
2. แยก `IssueForm`, `IssueList` และ `StatusBadge` เป็น Component ได้
3. ส่งข้อมูลเข้า Component ผ่าน Props ได้
4. ย้าย Type และ Mock Data ไปไว้ในไฟล์กลางได้
5. สร้าง Route `/issues`, `/issues/new` และ `/issues/[id]` ได้

### ไฟล์ที่จะได้หลังจบชั่วโมง

```text

    [id]/
      page.tsx
```

## Slide 2: Component และ Props คืออะไร

**Component** คือ Function ที่คืน UI และนำกลับมาใช้ซ้ำได้:

```tsx
export function StatusBadge() {
  return <span>OPEN</span>;
}
```

หาก Component ต้องแสดงข้อมูลที่เปลี่ยนไปในแต่ละครั้ง เราส่งข้อมูลเข้าไปผ่าน **Props**:

```tsx
<StatusBadge status="OPEN" />
```

Parent ส่ง `status` ผ่าน Props แล้ว `StatusBadge` ใช้ค่านั้นสร้าง UI ที่เหมาะกับแต่ละ Issue

คำว่า `export` ทำให้ไฟล์อื่น Import Component นี้ไปใช้ได้ ส่วนชื่อ Prop บอกว่า Component ต้องการข้อมูลอะไร

## Slide 13: App Router ใช้ Folder สร้าง URL

**App Router** ใช้ Folder ภายใน `app` กำหนดแต่ละ Segment ของ URL และใช้ `page.tsx` เป็น UI ของ Route นั้น:

| ไฟล์ | URL |
|---|---|
| `app/page.tsx` | `/` |
| `app/issues/page.tsx` | `/issues` |
| `app/issues/new/page.tsx` | `/issues/new` |
| `app/issues/[id]/page.tsx` | `/issues/001`, `/issues/002`, ... |

Folder `[id]` เป็น Dynamic Segment เครื่องหมาย `[ ]` บอกว่า Segment นี้เปลี่ยนค่าได้ตาม Issue ที่ผู้ใช้เปิด

## Slide 18: Dynamic Route รับ `id` จาก URL

Folder ที่ครอบชื่อด้วย `[ ]` คือ **Dynamic Segment** ดังนั้น `app/issues/[id]/page.tsx` จึงใช้ Route เดียวรองรับ Issue ได้หลายรายการ

เมื่อเปิด `/issues/001` Next.js จะส่งค่า `{ id: "001" }` เข้ามาทาง `params`

ใน Next.js เวอร์ชันนี้ `params` เป็น Promise หน้า Dynamic Route จึงต้องเป็น `async` และใช้ `await` ก่อนอ่านค่า

- `Promise<{ id: string }>` กำหนดว่า `params` จะให้ Object ที่มี `id`
- `async` ทำให้ Page Function ใช้ `await` ได้
- `const { id } = await params` รอค่าแล้วดึง `id` ออกมา
